# macOS signing and permissions / 签名与权限

The stable local installation uses:

- Bundle ID: `local.openfunasr.app`
- Signing identity name: `OpenFunASR Local Signing`
- App location: `/Applications/OpenFunASR.app`
- A certificate-pinned designated requirement generated by `sign_openfunasr_bundle.sh`

辅助功能、麦克风等隐私授权与应用身份有关。保持 Bundle ID、同一签名证书、指定要求及
安装位置连续，有助于正常更新保留授权；最终仍以新启动的应用进程和真实操作为准。
应用名称相同、系统开关显示已开启或签名验证通过，都不足以单独证明权限可用。

## First installation / 首次安装

Read [AI_INSTALL.md](docs/AI_INSTALL.md) before creating a signing identity. That
operation imports a newly generated private key and adds user-level code-signing
trust in the login Keychain. Only run it with the user's authorization:

```bash
./setup.sh --install --create-signing-identity
```

Retain that identity. Do not regenerate it for each build, share its private key,
or copy another user's certificate to make a local installation work. This
self-signed certificate is for a user's local builds; it is not Apple notarization.

首次安装后，在系统设置授权辅助功能和麦克风，然后重启 OpenFunASR。
安装脚本不会自动重置 TCC。

## Ordinary updates / 日常更新

```bash
./setup.sh --install
```

The installer verifies the old and candidate bundles, compares Bundle IDs and
designated requirements, stages the candidate, then replaces the app and runtime.
Its rollback restores the old app/runtime if installation fails. Settings and
logs remain in the user's Application Support folder.

The default identity is reused. The production install refuses ad-hoc signing.
On a signing mismatch, stop and diagnose. Do not alter Keychain, clear permissions,
or enable a migration override as a routine fix.

## Intentional identity migration / 有意迁移签名

Changing the certificate can require reauthorization. Only after explaining that
change and receiving approval, use the one-time migration flag documented in
[AI_INSTALL.md](docs/AI_INSTALL.md). Never set it by default or save it in a shell
profile. No ordinary update should reset privacy permissions.

## Acceptance / 验收

更新后检查新启动的 OpenFunASR 自身日志：

```text
startup permissions accessibility=已授权 microphone=已授权(3)
```

然后确认菜单栏图标和菜单可见，并在临时文本框完成一次真实的按键录音、转写和粘贴。
不要用旧日志、Terminal 的权限检查或单独发送成功的 CGEvent 代替验收。
需要单独检查常驻进程粘贴时，按安装文档中的可选测试执行。

If stable signing matches but permissions do not work, report the observed state.
Do not automatically reset permissions or promise permission continuity solely
because a signature matches.
